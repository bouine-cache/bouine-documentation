## 为什么现在做基准测试？

Bouine 还在 1.0 之前的阶段，但核心缓存管道 — 符合 RFC 9111 的 HTTP 缓存、零分配命中路径、基于 gossip 的集群感知 — 已经足够稳定，可以公布真实数据了。本文分享我们的第一批基准测试结果，并解释它们对生产部署的意义。

## 测试环境

| 组件 | 详情 |
|---|---|
| 硬件 | 单节点，AMD EPYC 7763，64 vCPU，256 GB 内存 |
| 操作系统 | Linux 6.6（内核调优，`net.core.somaxconn=65535`） |
| bouine | v0.5.0，默认配置，4 GB 磁盘缓存，1 GB 内存缓存 |
| 源站 | nginx 提供 10 000 个唯一的 64 KB 对象（200 OK，`Cache-Control: max-age=3600`） |
| 负载生成器 | `wrk2`，恒定速率调度，每次运行 10 分钟 |

## 命中路径延迟

任何 HTTP 缓存最关键的指标是缓存**命中**的延迟。Bouine 的命中路径设计为预热后零分配。

| 百分位 | bouine (p50) | nginx proxy_cache | Varnish |
|---|---|---|---|
| p50 | **0.18 ms** | 0.42 ms | 0.21 ms |
| p99 | **0.61 ms** | 1.83 ms | 0.74 ms |
| p99.9 | **1.24 ms** | 4.12 ms | 1.58 ms |

Bouine 的零分配命中路径在尾部表现最为明显：p99.9 比 nginx proxy_cache 低约 3 倍，比 Varnish 低 1.3 倍。

## 吞吐量

在 64 个并发连接和 100% 缓存命中率下：

| 缓存 | 请求/秒 | CPU 利用率 |
|---|---|---|
| bouine | **486 000 rps** | 38% |
| Varnish | 412 000 rps | 44% |
| nginx proxy_cache | 178 000 rps | 71% |

Bouine 在更低的 CPU 利用率下维持更高的吞吐量，这得益于零分配设计和 Go 高效的 goroutine 调度。

## 集群负载下的缓存命中率

使用 3 节点 bouine 集群（启用 gossip）和 50 000 个唯一对象，我们测量了工作集轮换时的稳态缓存命中率：

| 工作集轮换 | 命中率 (bouine) | 命中率 (单节点) |
|---|---|---|
| 0%（静态） | 100% | 100% |
| 每分钟 10% | **97.8%** | 91.2% |
| 每分钟 50% | **89.3%** | 72.1% |

基于 gossip 的 peer-fetch 协议即使在显著的工作集变化下也能保持集群范围的高命中率。单节点缓存退化更快，因为每次轮换都是冷未命中。
